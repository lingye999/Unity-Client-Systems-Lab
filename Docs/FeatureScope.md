# 功能边界和阶段计划

## 项目定位

这是一个 Unity 客户端系统实践项目，核心目标是展示模块化架构、数据驱动背包、红点通知、事件刷新、存档、性能分析和资源更新能力。

## 第一版背包范围

第一版需要形成完整闭环：

- 打开和关闭背包页面。
- 显示固定容量的物品格子。
- 显示图标、名称、数量、分类和详情。
- 添加、移除和堆叠物品。
- 拆分、移动和交换物品。
- 分类、排序、选中、拖拽、使用和丢弃。
- 通过事件刷新 UI，不让 UI 直接修改 Domain 数据。

## 后续模块

- 红点树和业务节点聚合。
- JSON 存档、版本号、默认值和损坏恢复。
- 50、200、1000 条数据的压力场景和 Profiler 对比。
- Canvas、布局、对象复用和局部刷新的优化。
- 客户端与 Minimal API 的同步原型。
- AssetBundle / Addressables 资源加载和远程更新。
- 随机地图生成和可复用的交互模块。

## 当前不纳入范围

完整角色装备、战斗系统、商城、账号登录、多人联机、复杂技能系统和正式美术包装。它们只有在核心系统稳定后才会作为独立模块评估。

## 验收原则

功能必须能在运行场景中演示；业务逻辑必须能独立测试；性能结论必须有相同条件下的基线和复测；教程或外部素材必须能解释来源和改写内容。
